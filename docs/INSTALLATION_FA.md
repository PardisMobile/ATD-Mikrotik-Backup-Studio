# راهنمای نصب و وضعیت فعلی

## وضعیت مخزن

در حال حاضر این مخزن شامل مستندات و فایل‌های اولیهٔ پنل/relay سرور است. سورس کامل کلاینت ویندوز و بستهٔ یکپارچهٔ نهایی هنوز در این مخزن قرار نگرفته است؛ بنابراین تا اضافه شدن آن، این مخزن را برای ساخت EXE یا نصب عملیاتی کامل فرض نکنید.

## آماده‌سازی بخش سرور

این بخش فقط زمانی کاربرد دارد که فایل‌های `server-deployment/send-backup.php`، `panel.css`، `panel.js` و `install-server.sh` را بررسی کرده و تنظیمات نمونه را با مقادیر خود جایگزین کرده باشید.

1. روی سرور، مسیر DocumentRoot واقعی سایت HTTPS موجود را پیدا کنید. مسیر را حدس نزنید.
2. پیش از تغییر، از فایل‌های مقصد نسخهٔ پشتیبان بگیرید.
3. مخزن را در مسیر موقت دریافت کنید:

   ```bash
   git clone https://github.com/PardisMobile/ATD-Mikrotik-Backup-Studio.git
   cd ATD-Mikrotik-Backup-Studio
   ```

4. ابتدا اسکریپت نصب را فقط بخوانید:

   ```bash
   less server-deployment/install-server.sh
   ```

5. **اسکریپت را تا زمانی که فایل PHP تنظیمات واقعی ندارد اجرا نکنید.** فایل PHP فعلی یک قالب نمونه با مقادیر `REPLACE_...` است؛ توکن بات، توکن relay، شناسهٔ مقصد، هش رمز و مسیر بکاپ باید به‌صورت امن تنظیم شوند. هرگز مقادیر محرمانه را در Git commit نکنید.
6. پس از آماده‌سازی فایل‌ها، دستور نصب به این شکل است؛ مسیر نمونه را با یک زیرپوشهٔ واقعی در DocumentRoot خود عوض کنید:

   ```bash
   sudo bash server-deployment/install-server.sh /ABSOLUTE/EXISTING/WEBROOT/atd-backup
   ```

   این دستور فقط فایل‌ها را به زیرپوشهٔ انتخاب‌شده کپی می‌کند و تنظیمات سراسری وب‌سرور یا پورت‌ها را تغییر نمی‌دهد. با این حال، قبل از اجرا باید فرض‌های اسکریپت دربارهٔ کاربر PHP و مسیرها را با سرور خود تطبیق دهید.

## ویندوز و روتر

کلاینت کامل ویندوز در حال حاضر هنوز در مخزن ثبت نشده است. پس از افزودن آن، مراحل مورد انتظار عبارت‌اند از اجرای `Generate-MikroTik-Backup.bat)، آزمایش SFTP، سپس ساخت EXE و در نهایت آزمایش ارسال تلگرام با یک بکاپ غیرحساس. تا آن زمان برای ساخت EXE به فایل ZIP کامل پروژه که قبلاً در گفت‌وگو تحویل شده بود نیاز دارید.

## چک‌لیست امنیت و تست

- از HTTPS استفاده کنید و توکن ربات/relay و رمزها را در Git قرار ندهید.
- PHP را با کاربر وب‌سرور اجرا کنید، نه root.
- از `chmod 777` استفاده نکنید.
- دسترسی به مسیر بکاپ را محدود کنید؛ مسیرهای زیر `/root` نیازمند بررسی دقیق ACL هستند.
- حذف فایل و ارسال مجدد را با فایل آزمایشی بررسی کنید.
- ارسال فایل ناقص، قطع شبکه، تلاش مجدد پس از راه‌اندازی مجدد، و جلوگیری از ارسال نسخهٔ یکسان باید آزمایش شوند.
- بخش تغییر رمز در نسخهٔ نمونه هنوز نیازمند تکمیل اتصال به تنظیمات امن است؛ آن را قابلیت تکمیل‌شده فرض نکنید.
