# راهنمای نصب ATD MikroTik Backup Studio

## خروجی ویندوز

1. برنامه EXE/ژنراتور را اجرا و مقادیر موردنیاز را وارد کنید. سرور SFTP باید همان سرور لینوکسی باشد که پنل روی آن نصب می‌شود و مسیر بکاپ باید مسیر واقعی مطلق فایل‌سیستم باشد، نه مسیر نسبی داخل SFTP chroot.
2. در حالت Telegram/Panel، پورت HTTPS عمومی را انتخاب کنید (پیش‌فرض `24443`). این پورت باید هنگام نصب آزاد باشد و در صورت نیاز در فایروال ارائه‌دهنده مجاز شود.
3. فایل `generated-output/install.sh` تنظیمات محرمانه همان نصب را دارد؛ آن را در گیت‌هاب یا فضای عمومی قرار ندهید.
4. فایل `paste-into-routeros-terminal.txt` برای نصب اسکریپت و زمان‌بندی روی MikroTik ساخته می‌شود.

در حالت SFTP-only نیازی به پنل و `install.sh` نیست؛ خروجی RouterOS و در صورت نیاز `create-sftp-directory.txt` را استفاده کنید.

## نصب سرور (حالت Telegram/Panel)

1. فقط فایل `install.sh` را به سرور لینوکس منتقل کنید.
2. اجرا کنید:

   ```bash
   sudo bash install.sh
   ```

3. اسکریپت فایل‌های پنل را از GitHub دریافت و SHA-256 آن‌ها را بررسی می‌کند. در صورت عدم تطابق نسخه‌ها نصب متوقف می‌شود.
4. تنظیمات خصوصی در `/etc/atd-mikrotik-backup-studio/config.php` ایجاد می‌شوند. تنظیمات نشست‌های ورود در مسیر داده اختصاصی ATD ذخیره می‌شوند.
5. آدرس واقعی پنل در پایان نمایش داده می‌شود: `https://HOST:PORT/send-backup.php`. نصب مجدد، پورت تخصیص‌یافته را حفظ می‌کند؛ اگر فایل تولیدشده پورت دیگری داشته باشد، نصب متوقف می‌شود تا URL روتر و سرور ناهمسان نشوند.
6. اسکریپت MikroTik فقط از SFTP استفاده می‌کند و هیچ درخواست HTTP یا تلگرامی نمی‌فرستد. Cron اختصاصی ATD روی لینوکس هر دقیقه پوشهٔ بکاپ را بررسی می‌کند، فایل‌های جدید را پس از پایدار شدن حجمشان به تلگرام می‌فرستد و برای جلوگیری از ارسال تکراری، وضعیت و هش فایل را نگه می‌دارد.
7. بعد از ورود به پنل، از بخش تنظیمات تلگرام Bot Token و Chat ID را وارد کنید و پیام آزمایشی بفرستید؛ جنراتور ویندوز این دو مقدار را نمی‌پرسد.
7. گواهی پیش‌فرض self-signed است و ممکن است مرورگر هشدار نشان دهد. برای استفاده عمومی، دامنه و گواهی معتبر توصیه می‌شود.
8. اگر دسترسی بیرونی مسدود است، پورت TCP نمایش‌داده‌شده را در فایروال سرور یا پنل ارائه‌دهنده، پس از بررسی سیاست موجود، مجاز کنید. نصب‌کننده خودش قوانین کلی فایروال را تغییر نمی‌دهد.

## به‌روزرسانی

پیش‌نیاز: سرویس Cron موجود در میزبان باید از قبل فعال و برای راه‌اندازی خودکار فعال شده باشد. نصب‌کننده و به‌روزرسان فقط فایل‌های اختصاصی ATD را در `/etc/cron.d` مدیریت می‌کنند و سرویس یا بستهٔ Cron مشترک میزبان را نصب، فعال، متوقف یا تعمیر نمی‌کنند؛ در غیر این صورت با `HOST_CRON_NOT_READY` متوقف می‌شوند.

برای به‌روزرسانی نصب موجود، دستور زیر را در ترمینال سرور اجرا کنید. updater کد پنل را بررسی و جایگزین می‌کند، تنظیمات خصوصی، بکاپ‌ها و واحدهای systemd موجود را حفظ می‌کند و فقط وظایف Cron اختصاصی ATD را مدیریت می‌کند؛ اسکریپت MikroTik و تنظیمات وب‌سرورهای دیگر تغییر نمی‌کنند. پنل Worker پس‌زمینه ایجاد یا اجرا نمی‌کند:

```bash
sudo atd-mikrotik-backup-update
```

به‌روزرسانی کد پنل را در مسیر موقت دریافت و بررسی می‌کند، از کد قبلی نسخه پشتیبان می‌گیرد و فایل‌های برنامه و helperهای ATD را جایگزین می‌کند. تنظیمات اولیه، رمزهای ذخیره‌شده، سابقه ارسال، فایل‌های بکاپ و سرویس‌ها/Timerهای systemd حفظ می‌شوند. فقط سرویس‌های PHP/TLS خود ATD که پیش از به‌روزرسانی فعال بوده‌اند restart می‌شوند.

## وضعیت آزمون

موفقیت CI به معنی آزمون کامل روی سرور واقعی نیست. قبل از استفاده عملیاتی، نصب و به‌روزرسانی را روی یک سرور آزمایشی بررسی کنید و ارسال واقعی SFTP و تلگرام را آزمایش کنید.
