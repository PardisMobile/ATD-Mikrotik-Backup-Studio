# GitHub-based server updates and configuration preservation

## Required invariant

A customer's values collected by the PowerShell generator must not be overwritten by an update. This includes the SFTP host/user/remote directory, relay token, Telegram bot token, Chat ID, panel password salt/hash, backup directory, and existing state/database data.

## Current safe behavior

Run:

```bash
sudo bash install-server.sh --update /absolute/path/to/installed/panel
```

The updater downloads assets over HTTPS, stages them before deployment, backs up existing files, and validates PHP syntax. It detects the legacy PHP schema generated by the current PowerShell generator (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `PANEL_PASSWORD_SALT`, `PANEL_PASSWORD_HASH`, `BACKUP_DIR`) and **does not replace that PHP file**. It can update the static CSS/JS assets only in that case. This conservative behavior is intentional: the GitHub PHP template uses a different constant/state schema and must not be substituted until a schema-compatible migration exists.

## Rules for future PHP updates

- Never replace the whole generated PHP file if it contains customer configuration.
- Prefer separating customer-specific values into a private server-side config file outside the public web root, created once by the initial installer with restrictive permissions.
- A PHP update must replace application code only; it must not overwrite private config or existing state/database files.
- Database/state changes must be additive migrations: create new tables/columns/keys only when absent, preserve existing rows and values, and never drop or reset customer data during routine updates.
- Take a database/state backup before migration and abort/rollback on validation failure.
- Test upgrade from the previous generated schema and verify all customer values and existing state remain byte-for-byte unchanged.

## Integration status

The original full PowerShell generator must be present in the repository and updated so the generated server script includes the update command and its usage. Until that exact source is committed and tested, the complete new-PC-to-EXE workflow is not certified as integrated.
